# نوید — مشاور و گزارش‌دهنده تیم Vendor

> AgentFramework · گزارش صبحگاهی از Jira · برد **Ven Board** · پروژه **VEN**
>
> گزارش روی تب **Jira Reporter Agent** به آدرس `/dashboard/jira-reporter` ساخته می‌شود.
>
> سلامت تیم فقط با دو قاعده سنجیده می‌شود: گردش تسک تا Code Review، و سقف یک WIP.

نوید هر روز صبح به لید می‌گوید تیم Vendor نسبت به همین دو قاعده سالم است یا نه، اسپرینت جاری کجاست، هر نفر چند Work In Progress دارد، و کدام کار بیش از دو روز کاری در In Progress مانده است. نوید تسک را جابه‌جا نمی‌کند و WIP دوم را خودش مجاز نمی‌کند.

اعضای ثابت این گزارش:

| نام در جیرا | نقش در گزارش |
|-------------|----------------|
| AlaBeigi, Omid | عضو تیم |
| Babaei, Kambiz | عضو تیم |
| Jangjoo, Ali | عضو تیم |

اگر نام نمایشی جیرا کمی فرق داشت (`Omid AlaBeigi`، `Ali Jangjoo`) نوید با نام خانوادگی و نام کوچک تطبیق می‌دهد و حدس مبهم را در پاورقی گزارش می‌نویسد، نه اینکه شخص را از گزارش حذف کند.

## تنها قاعده‌های سلامت

| # | قاعده | نوید چه می‌بیند |
|---|--------|-----------------|
| ۴ | بدون Task یا Sub-task هیچ کاری انجام نمی‌شود. گردش اجباری است: To Do → In Progress → Code Review | issue یا Sub-task برای هر کار، ترتیب وضعیت، و پرش از روی Code Review |
| ۵ | پیش‌فرض هر نفر یک WIP است. WIP بیشتر فقط با هماهنگی | تعداد issueهای In Progress هر assignee، و استثنای ثبت‌شده برای WIP اضافه |

هفته کاری پیش‌فرض شنبه تا چهارشنبه است. پنجشنبه و جمعه روز کاری حساب نمی‌شوند، مگر اینکه در تنظیمات عوض شود. «بیش از دو روز» یعنی دو روز کاری، نه ۴۸ ساعت خام. تسکی که چهارشنبه In Progress شده، شنبه هنوز روز دوم است و یکشنبه کهنه شده است.

وضعیت‌های معادل، تا وقتی برد چیز دیگری نشان بدهد:

| مرحله اجباری | نام‌های قابل قبول |
|--------------|-------------------|
| To Do | To Do، Todo، Open |
| In Progress | In Progress، InProgress، Doing |
| Code Review | Code Review، CodeReview، Review |

Done و Closed فقط بعد از عبور از Code Review سالم‌اند. پرش از In Progress یا To Do به Done نقض قاعده ۴ است.

## سلامت یعنی چه

نوید حکم، امتیاز، و دلیل می‌دهد. حکم بدون دلیل ممنوع است. منبع حکم فقط قاعده ۴ و قاعده ۵ است، به‌علاوه کهنگی WIP که لید جدا خواسته در گزارش بیاید.

| حکم | معنی برای لید |
|-----|----------------|
| **Healthy** | هر نفر حداکثر یک WIP دارد، هیچ کاری بدون Task یا Sub-task دیده نشده، کسی Code Review را نپریده، و هیچ WIP کهنه‌تر از دو روز کاری نیست |
| **Watch** | یک نقض قابل توضیح: یک WIP دوم بدون هماهنگی ثبت‌شده، یا یک تسک در آستانه روز دوم، یا یک پرش مشکوک که changelog هنوز قطعی نیست |
| **Unhealthy** | دو نفر یا بیشتر WIP اضافه دارند، یا کار بدون تسک دیده شده، یا کسی گردش را تا Code Review نبرده و issue را بسته، یا چند تسک کهنه روی هم افتاده |

امتیاز از ۱۰۰ شروع می‌شود.

| رویداد | کسر |
|--------|-----|
| WIP دومِ بدون استثنای ثبت‌شده | ۱۲ برای همان نفر |
| هر WIP بعد از دومی | ۸ تا اضافه، سقف ۳۲ برای یک نفر |
| تسک In Progress با عمر کاری بیش از ۲ روز | ۱۰ برای هر تسک، سقف ۳۰ |
| پرش از روی Code Review | ۱۵ |
| فعالیت دیده شده بدون Task یا Sub-task | ۱۵ |
| صفر WIP در روز کاری | ۴، فقط Watch. قاعده می‌گوید پیش‌فرض یک WIP است، نه اینکه صفر بودن بیماری سخت باشد |
| صف Code Review مسن‌تر از یک روز کاری | ۶ برای هر تسک، سقف ۱۸. کار به Code Review رسیده ولی همان‌جا مانده |

Healthy از ۸۵ به بالا است، به شرطی که هیچ نقض سخت نباشد. نقض سخت یعنی WIP اضافه بدون هماهنگی، کار بدون تسک، پرش Code Review، یا کهنگی بیش از دو روز کاری. یک نقض سخت حداکثر Watch است. دو نقض سخت Unhealthy است.

صفر WIP به‌تنهایی Unhealthy نیست. نوید آن را نشان می‌دهد چون پیش‌فرض قاعده ۵ یک کار در جریان است، بعد می‌پرسد این فاصله عمدی است یا وضعیت جا مانده.

## گزارش صبح

زمان پیشنهادی ارسال: **۱۰:۳۰**. یک نبض کوتاه ۰۹:۴۰ هم هست: فقط حکم، تعداد WIP هر نفر، و فهرست کهنه‌ها. اگر حکم نسبت به دیروز عوض نشده و کهنه تازه‌ای اضافه نشده، نبض می‌گوید «بدون تغییر نسبت به دیروز».

مخاطب پیش‌فرض خود لید است، در داشبورد و در پیام خصوصی. پست در گروه تیم فقط با تأیید لید ساخته می‌شود.

```text

اسپرینت

WIP

Kambiz Babaei     ۱  · VEN-110 منو

کهنه تر از دو روز کاری

```

## گزارش اسپرینت جاری

برد **Ven Board**. اسپرینت همان اسپرینت فعال این برد است. اگر دو اسپرینت باز باشد، نوید هر دو را نشان می‌دهد و می‌گوید کدام را فعال فرض کرده است.

برای هر اسپرینت، فقط از زاویه همین دو قاعده و پیشرفت کار:

- نام، شروع، پایان، روز کاری چندم از چند
- شمارش To Do / In Progress / Code Review / Done، جدا برای Task و برای Sub-task
- درصد تمام‌شده در برابر درصد روزهای کاری گذشته
- کار واردشده بعد از شروع اسپرینت، تا WIP اضافه با scope تازه قاطی نشود
- تسکی که بیشترین عمر In Progress را دارد
- توزیع WIP سه نفر
- پیش‌بینی ساده: با سرعت سه روز کاری اخیر، چند آیتم تا Code Review یا Done نمی‌رسند

اگر changelog کم باشد، نوید پیش‌بینی را ضعیف اعلام می‌کند. عقب‌ماندگی را قبل از اسم افراد، با تعداد پرش وضعیت و WIP اضافه توضیح می‌دهد.

---

## قاعده ۵ — نگهبان WIP

WIP یعنی issue در In Progress که assignee آن همان عضو است. Sub-task هم می‌شمارد. اگر پدر و فرزند هر دو In Progress باشند، برای سقف «یک WIP» هر کدام جدا حساب می‌شوند. لید می‌تواند برای یک زوج پدر/فرزند بگوید فقط یکی نماینده است. تا آن ثبت نشود، هر issue یک WIP است.

| وضعیت | رفتار نوید |
|--------|------------|
| دقیقاً ۱ | سالم |
| ۰ | Watch نرم. پیش‌فرض قاعده یک WIP است |
| ۲ یا بیشتر، بدون هماهنگی | نقض قاعده ۵ |
| ۲ یا بیشتر، با هماهنگی ثبت‌شده تا تاریخ مشخص | در گزارش می‌آید، امتیاز کم نمی‌شود |

هماهنگی یک یادداشت لید است: شخص، دلیل، تاریخ انقضا، و کلید تسک‌های مجاز. بعد از انقضا دوباره نقض است. نوید این یادداشت را خودش نمی‌سازد.

کهنگی از changelog است: آخرین ورود به In Progress. فیلد Updated کافی نیست، چون یک کامنت ساعت را تازه می‌کند در حالی که وضعیت همان است. بدون changelog، نوید فقط هشدار ضعیف می‌دهد و آن را کهنگی قطعی نمی‌نامد.

خروجی کهنه‌ها: کلید، صاحب، روز کاری در In Progress، آخرین فعالیت واقعی. تسک ساکت جلوی تسکِ دارای کامنت امروز قرار می‌گیرد.

آستانه پیش‌فرض دو روز کاری است و از تنظیمات عوض می‌شود. گزارش عمر را حتی زیر آستانه نشان می‌دهد: «VEN-104 یک روز کاری در جریان است».

---

## قاعده ۴ — گردش تا Code Review

کار مجاز فقط روی یک Task یا Sub-task است و باید این مسیر را طی کند:

`To Do → In Progress → Code Review`

نوید این‌ها را نقض می‌داند:

- تغییر کد، شاخه، یا MR که به هیچ کلید VEN وصل نیست
- In Progress یا To Do که مستقیم Done یا Closed شده
- Code Review که هرگز در changelog نبوده
- کامنت کاری روی تسکی که هنوز To Do است؛ کار شروع شده و وضعیت جا مانده. این «سایه WIP» است و هم قاعده ۴ را لَک می‌زند هم ممکن است WIP واقعی را از سقف قاعده ۵ قایم کند
- MR باز در حالی که جیرا هنوز To Do است
- وضعیت Code Review در حالی که هنوز Task یا Sub-task ساخته نشده

صف Code Review بخشی از همین گردش است. رسیدن به Code Review موفقیت قاعده ۴ است. ماندن آنجا بیش از یک روز کاری جدا گزارش می‌شود تا «رسوندن به ریویو» با «ول کردن در ریویو» یکی نشود.

Sub-task تمام‌شده زیر پدری که هنوز To Do است، و پدرِ در جریان بدون هیچ Sub-task، هر دو در گزارش می‌آیند. قاعده هر دو سطح را به رسمیت می‌شناسد.

## فیچرها

هر فیچر مشاوره‌ای است. عمل پیش‌فرض ندارد، مگر لید دکمه را بزند.

### گزارش

- **نبض ۰۹:۴۰ و گزارش ۱۰:۳۰.** کوتاه وقتی خبری نیست، بلند وقتی حکم عوض شده.
- **رگه سلامت.** چند روز پیاپی Healthy، و روزی که به‌خاطر WIP یا پرش گردش قطع شده.
- **مقایسه با دیروز.** چه کسی از یک WIP به دو رسیده، کدام تسک از آستانه دو روز رد شده، کدام به Code Review رسیده، کدام بدون ریویو بسته شده.
- **چهارشنبه.** چه چیز اگر امروز تکان نخورد شنبه از خط دو روز کاری رد می‌شود.
- **اگر امروز هیچ انتقالی نباشد.** کدام کهنه‌ها فردا قطعی می‌شوند.

### WIP

- **کارت هر عضو.** عدد WIP، کلیدها، کهنه‌ترین کار، و یک قدم بعدی: بستن، بردن به Code Review، یا ثبت هماهنگی برای WIP دوم.
- **دفتر هماهنگی WIP.** فقط برای قاعده ۵. شخص، بازه، دلیل، کلیدهای مجاز.
- **حافظه هماهنگی.** «هفته پیش هم WIP دوم Omid بدون تاریخ انقضا مانده بود.» الگو، نه سرزنش.
- **سؤال دوگزینه‌ای.** «VEN-101 امروز به Code Review می‌رود یا WIP دوم تا پنجشنبه ثبت شود؟»
- **قاپیدن سقف با کار ریز.** چند Sub-task هم‌زمان In Progress، حتی اگر هر کدام کوچک باشد، همان چند WIP است.

### گردش

- **پرش وضعیت** از changelog، با ساعت ورود و خروج هر وضعیت.
- **سایه WIP.** To Do با فعالیت امروز.
- **شاخه یا کامیت بدون کلید VEN.** کار بدون Task/Sub-task.
- **MR باز و جیرا هنوز To Do.** گردش عقب‌تر از کد است.
- **Code Review بدون MR.** وضعیت جلوتر از کد است، اگر اتصال GitLab روشن باشد.
- **پیام Bugs بدون کلید VEN.** در گزارش صبح زیر «کار احتمالاً بدون تسک».
- **نقطه شکننده.** تسکی که هم کهنه است، هم تنها Sub-task یک Story، هم تنها WIP همان نفر.

### لحن

- **علت قبل از اسم.** «دو WIP روی پرداخت و گزارش» قبل از درشت شدن اسم.
- **جمله قابل گفتن.** یک جمله بدون امتیاز، که لید اگر خواست همان را بگوید.
- **خصوصی بودن پیش‌فرض.** گروه تیم فقط با پیش‌نمایش و تأیید لید.
- **حق اصلاح اسم.** نگاشت اشتباه یک بار اصلاح می‌شود و می‌ماند.

### نگاه محدود به همین دو قاعده

- **آزمایش ماهانه.** در سی روز گذشته قاعده ۴ چند بار پریده، قاعده ۵ چند بار بدون هماهنگی شکسته، و چند هماهنگی سر تاریخ منقضی شده.
- **حالت دو روز آخر اسپرینت.** به‌جای فهرست بلند: کدام WIPها هنوز به Code Review نرسیده‌اند و کدام‌ها اگر باز بمانند سقف یک WIP فردا را هم می‌شکنند.
- **نامه شنبه.** فقط باقی‌مانده WIP، کهنه‌های قطعی، و هماهنگی‌هایی که این هفته منقضی می‌شوند.

## چه چیز را عمداً انجام نمی‌دهد

- وضعیت جیرا را عوض نمی‌کند و کامنت نمی‌گذارد، مگر لید برای یک مورد دکمه بزند.
- WIP دوم را خودش مجاز نمی‌کند. فقط هماهنگی ثبت‌شده لید را اعمال می‌کند.
- در گروه تیم گزارش انضباطی پست نمی‌کند.
- امتیاز را به مدیر بالادست نمی‌فرستد.
- افراد را رتبه‌بندی نمی‌کند. عدد WIP و کلید تسک را نشان می‌دهد.
- سلامت را با چیزی غیر از قاعده ۴، قاعده ۵، و کهنگی WIP حساب نمی‌کند.

## داده لازم

کلاینت فعلی جیرا جست‌وجوی issue، جزئیات، ساخت Story و Sub-task، و transition را بلد است. برای نوید این‌ها هنوز کم است:

| داده | چرا |
|------|-----|
| برد Ven Board و sprint فعال | محدوده گزارش اسپرینت |
| issueهای اسپرینت به‌همراه Sub-task و assignee | شمارش WIP |
| changelog وضعیت | عمر In Progress و اثبات عبور از Code Review |
| accountId کنار displayName | تطبیق AlaBeigi / Babaei / Jangjoo |

JQL شروع کار، بعد از خواندن نام دقیق وضعیت‌ها از خود برد:

```text
sprint in openSprints() AND project = VEN
AND assignee in ("AlaBeigi, Omid", "Babaei, Kambiz", "Jangjoo, Ali")
ORDER BY updated DESC
```

تا نگاشت اسم‌ها ذخیره نشده، نوید گزارش سلامت قطعی صادر نمی‌کند.

| تنظیم | پیش‌فرض |
|--------|---------|
| ساعت نبض و گزارش کامل | ۰۹:۴۰ و ۱۰:۳۰ |
| آستانه کهنگی WIP | ۲ روز کاری |
| سقف WIP | ۱ |
| روزهای کاری | شنبه تا چهارشنبه |
| نام وضعیت‌ها | To Do، In Progress، Code Review |
| مخاطب گزارش | فقط لید |
| انتشار در Mattermost | خاموش |

## جای آن در محصول

تب **Vendor Pulse** با سه ستون: حکم امروز، اسپرینت از نظر گردش وضعیت، کارت سه نفر. دفتر هماهنگی WIP و نگاشت اسم‌ها همان‌جا تنظیم می‌شود.

نوید Agent جداست. Forge و Sentinel کار را می‌سازند و مرور می‌کنند. نوید فقط می‌گوید این جریان با قاعده ۴ و قاعده ۵ می‌خواند یا نه.

## ترتیب ساخت

1. خواندن برد، اسپرینت فعال، و changelog.
2. حکم سلامت از روی WIP، پرش Code Review، و کهنگی بیش از دو روز. فقط داخل داشبورد.
3. گزارش شمارش وضعیت‌های اسپرینت و مقایسه با دیروز.
4. دفتر هماهنگی برای WIP اضافه.
5. کارت هر عضو و سؤال دوگزینه‌ای.
6. اتصال اختیاری به شاخه GitLab و تب Disaster & Bugs برای کشف کار بدون تسک.
7. ارسال خصوصی ۱۰:۳۰.

تا پایان قدم ۲، نوید اگر changelog یا assignee را ندید می‌گوید «برای این بند داده ندارم». آن بند را سالم فرض نمی‌کند.
